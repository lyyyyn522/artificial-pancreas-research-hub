# 血糖预测基线与模型类别

> **笔记性质：** 血糖预测模型的知识地图  
> **适用范围：** 科研与学习  
> **重要边界：** 本文介绍研究方法，不推荐个人治疗模型，也不提供自动给药算法。

## 1. 为什么先建立基线？

研究一个复杂模型前，应先知道简单方法能够达到什么表现。否则，即使复杂模型给出一个看起来不错的误差数值，也无法判断它是否真正带来改进。

**基线模型（baseline）**是用来比较的明确方法。它可以很简单，但必须与复杂模型使用：

- 相同的预测任务和目标；
- 相同的训练、验证、测试边界；
- 相同的预测时距；
- 相同的信息可获得条件；
- 相同的评价指标和计算代码。

基线不仅是“最低门槛”，也是检查数据处理、标签构造和评价程序是否合理的重要工具。

## 2. 最简单的基线：持续值预测

**持续值基线（persistence / zero-order）**假设未来的 CGM 值等于预测时刻最近一个可用的 CGM 值：

```text
预测的 G(t + H) = 在 t 时刻最近可用的 CGM 值
```

其中 `t` 是发出预测的时刻，`H` 是预测时距。

它不需要训练参数，但仍需明确：

- 最近读数距离 `t` 有多远；
- 如果 `t` 附近缺失读数，是否排除该样本；
- 不同预测时距是否使用同一输入；
- 预测目标是 CGM 值还是其他参考测量。

GluPredKit 将这类方法列为 `zero_order`，用于血糖预测基准比较。[1]

**局限：** 它没有显式利用进餐、胰岛素、活动或近期变化趋势；在快速变化的时段可能不足。

## 3. 简单趋势基线

可以使用最近若干个**预测时已可获得**的 CGM 值，估计近期变化趋势，并将其外推到目标时刻。

这类方法比持续值多利用了变化信息，但可能放大噪声或短暂波动。因此，必须记录：

- 用了多少个历史读数；
- 采样间隔如何处理；
- 是否做平滑以及平滑是否使用未来值；
- 缺失读数如何处理；
- 外推结果是否经过事先规定的限制或变换。

趋势基线也需在验证集上确定设置，不能根据最终测试结果反复修改。

## 4. 常见预测模型类别

| 类别 | 示例 | 主要思路 | 研究时重点检查 |
| --- | --- | --- | --- |
| 简单基线 | 持续值、简单趋势 | 用当前水平或近期变化推测未来 | 是否使用预测时可获得的信息 |
| 统计时间序列模型 | AR、ARIMA 等 | 利用历史序列的统计结构 | 平稳性、数据量、参数与更新方式 |
| 线性机器学习 | 线性回归、Ridge | 从历史读数及特征学习映射 | 特征构造、正则化与可解释范围 |
| 非线性机器学习 | 随机森林、支持向量回归等 | 学习非线性输入—输出关系 | 特征、样本量、个体泛化 |
| 深度学习 | LSTM、TCN、Transformer 等 | 从时序窗口学习较复杂的模式 | 训练数据、参数量、复现性及过拟合 |
| 生理或机制模型 | 葡萄糖—胰岛素动力学相关模型 | 用生理过程描述状态变化 | 模型假设、参数辨识和输入可获得性 |
| 混合模型 | 机制模型与数据驱动方法结合 | 结合不同方法的优势 | 每一部分的贡献是否可单独验证 |

这是**方法分类**，不是性能排名。GluPredKit 和 GlucoBench 展示了多个模型与基准实验的组织方式；它们的实现、输入要求和数据处理条件各有区别。[1][2]

## 5. “用了更多信息”与“模型更好”要分开

假设模型 A 只使用 CGM，模型 B 使用 CGM、进餐和胰岛素记录。如果 B 的误差更低，不能立即把全部提升归因于模型架构，因为它还获得了更多信息。

建议至少设计两个层次的比较：

1. **相同输入比较：** 两个模型都只使用相同的 CGM 历史；
2. **增加输入的比较：** 固定模型或明确控制其他条件，再研究加入进餐、胰岛素等信息是否带来改进。

同时报告辅助变量的缺失率及其在预测时是否真实可用。不能用事后补录的事件信息冒充实时预测输入。

## 6. 个体化模型与群体模型

- **个体化模型：** 主要使用目标个体自己的历史数据建立或调整模型。
- **群体模型：** 使用多名受试者的数据训练，再预测新数据。
- **群体预训练＋个体适配：** 先使用群体数据，随后使用目标个体允许的早期数据调整。

三者回答的问题不同。比较时应写明每个模型训练阶段使用了哪些受试者、哪些时间段、多少数据，以及测试受试者是否曾参与训练或适配。

## 7. 复杂模型需要额外报告什么？

对于需要训练的模型，建议至少记录：

| 项目 | 应记录的内容 |
| --- | --- |
| 实现来源 | 自行实现、论文作者代码或第三方库及版本 |
| 输入 | CGM 历史窗口和辅助变量 |
| 输出 | 单点、轨迹或事件概率 |
| 参数量或模型复杂度 | 适合该模型的复杂度描述 |
| 数据量 | 训练受试者数、有效窗口数 |
| 训练配置 | 超参数、训练轮次、随机种子 |
| 模型选择 | 验证集、选择准则 |
| 资源需求 | 训练与推理环境、耗时 |
| 结果 | 逐时距、逐受试者及重要区间的表现 |
| 局限 | 缺失数据、个体差异、分布变化等 |

模型越复杂，越要关注能否复现，而不是只展示一次最佳结果。

## 8. 预测模型与控制算法不要混为一谈

**预测模型**输出未来血糖值、轨迹或风险估计。

**控制算法**根据当前状态、预测结果及系统约束，决定如何调整系统行动。人工胰腺控制研究中出现过模型预测控制（MPC）、比例—积分—微分控制（PID）等方法。一项随机交叉研究曾在其特定受监测条件下比较个体化 MPC 与 PID 控制；这属于**控制方法比较**，不是血糖预测基线排名。[3]

```text
历史 CGM 等信息 → 预测模型 → 未来状态估计
                         ↓
传感器及系统状态 → 控制算法 → 系统行动 → 后续状态
```

预测模型可以被控制算法使用，但较低的离线预测误差不自动证明闭环系统表现更好。[4]

本篇只建立模型分类；控制算法实现与实验结果应分别放到 `models/` 和 `experiments/`。

## 9. 建议的第一轮预测模型阶梯

在真正开始复现实验时，可以从小到大逐步比较：

1. **持续值基线：** 确认标签、单位和指标计算正确；
2. **简单趋势基线：** 检查近期变化是否提供额外信息；
3. **一种线性模型：** 检查历史窗口或简单特征的价值；
4. **一种非线性模型：** 检查非线性方法是否有稳定收益；
5. **一种深度学习模型：** 在相同测试条件下评价更复杂方法。

每增加一种模型，都应回答：“相较于前面的基线，改进发生在哪些受试者、时距和场景？”而不是只报告总体平均指标。

这个阶梯是**研究组织建议**，不是已经验证的模型优劣顺序。

## 10. 公平比较检查清单

- [ ] 模型是否解决同一个预测任务？
- [ ] 目标测量方式与葡萄糖单位是否相同？
- [ ] 预测时距、历史窗口是否相同？
- [ ] 训练／验证／测试是否遵守同一划分？
- [ ] 输入变量是否相同？若不同，是否单独分析？
- [ ] 缺失值与异常值处理是否一致？
- [ ] 超参数是否只根据训练和验证数据确定？
- [ ] 是否与持续值等简单基线比较？
- [ ] 是否报告受试者数、有效窗口数与失败案例？
- [ ] 结果是否区分离线预测与闭环控制？
