# CGM 数据预处理：从原始记录到预测样本

> **笔记性质：** 血糖预测研究的数据处理规范  
> **适用范围：** 科研与学习  
> **重要边界：** 本文不提供个人医疗建议，不把处理后的数据用于真实设备给药。

## 1. 为什么要预处理？

连续血糖监测（CGM）数据看起来是一串“时间—葡萄糖值”，但真实导出文件可能存在时间戳格式不统一、采样间隔不规则、缺失读数、重复记录、单位不同或传感器更换等情况。

预处理的目的不是把曲线修饰得更平滑，而是：

1. 明确每条记录代表什么；
2. 找出可能影响分析的数据质量问题；
3. 采用事先说明、可复现的规则处理数据；
4. 保证预测模型只使用预测时刻实际可获得的信息。

**原始数据应保留不变。** 清理后的数据、处理规则和被排除记录的数量应另行保存。

## 2. 先建立数据字段清单

拿到数据后，先不要立即填补缺失值或生成滑动窗口。应先记录：

| 项目 | 需要核对的问题 |
| --- | --- |
| 数据来源 | 数据集、设备、研究及获取版本是什么？ |
| 受试者标识 | 能否区分不同受试者？标识是否经过适当去标识化？ |
| 时间戳 | 含不含日期、时区和夏令时信息？表示测量时间还是上传时间？ |
| 葡萄糖值 | 单位是 `mg/dL`、`mmol/L`，还是其他表示？ |
| 采样间隔 | 设备标称间隔和实际相邻记录间隔是否一致？ |
| 设备状态 | 能否识别传感器更换、校准或无效读数？ |
| 辅助事件 | 进餐、胰岛素和活动记录的时间戳分别表示什么？ |
| 使用条件 | 数据许可是否允许当前研究和衍生文件的分享？ |

不同 CGM 数据集的字段和采样频率可能不同。GlucoBench 为不同数据集提供配置与预处理代码，是学习如何记录数据集差异的一个例子。[1]

## 3. 推荐的处理顺序

```text
登记来源与许可
    ↓
读取原始文件并保留副本
    ↓
核对字段、时间戳和单位
    ↓
按受试者与时间排序，检查重复和异常
    ↓
统计缺失段与实际采样间隔
    ↓
确定研究任务及训练／验证／测试边界
    ↓
仅在允许的信息范围内进行填补或特征变换
    ↓
构造历史输入窗口和未来预测目标
    ↓
记录每一步保留与排除的样本数
```

有些操作（例如解析时间格式、统一已知单位）可以在划分前完成；**需要从数据中学习参数的操作**（例如计算归一化均值与标准差）必须遵守训练、验证和测试的边界。具体划分规则将在 `06-data-splitting-and-leakage.md` 中整理。

## 4. 时间戳：最先核对的问题

时间戳错误会让模型把本不同时发生的事情错误地对齐。至少检查：

- 是否为同一受试者的记录；
- 时间格式是否可解析；
- 是否记录了时区，或者数据说明明确采用哪个时区；
- 是否存在重复时间、倒序记录或不合理的时间跳跃；
- 传感器测量时间与平台接收、上传时间是否被混用；
- 进餐和胰岛素事件是否与 CGM 使用相同的时间基准。

**不要在不记录原因的情况下直接删除重复时间戳。** 先检查重复行是完全相同的导出副本，还是同一时间对应不同来源或不同状态的记录。

跨时区或夏令时转换时，应保留原始时间字段，并记录转换规则。

## 5. 单位：先确认，再转换

CGM 数据常使用 `mg/dL` 或 `mmol/L` 表示葡萄糖浓度。

处理时应：

1. 从数据说明或设备导出信息核实原始单位；
2. 选择实验统一使用的单位；
3. 记录转换规则及转换前后的字段名称；
4. 检查图表、阈值、评价代码是否使用相同单位。

**不能只根据数值大小猜测单位。** 如果单位无法可靠确认，应标记待核实，而不是静默转换。

## 6. 实际采样间隔与重采样

设备可能有标称采样间隔，但导出的实际时间序列不一定严格等间隔。应先计算相邻记录的时间差，并报告：

- 常见间隔；
- 不规则间隔所占比例；
- 较长缺失段的数量与长度；
- 不同受试者是否存在明显差异。

如果模型要求规则时间网格，可以考虑重采样，但需要明确：

- 目标时间网格如何确定；
- 原记录怎样映射到网格；
- 空缺网格是否填补；
- 填补后的值与真实观测值如何区分。

AGATA 工具提供将 CGM 数据映射到规则时间网格及处理缺失值的功能，但工具提供某种方法，**不代表该方法适用于所有预测任务**。[2]

## 7. 缺失值：先描述，再决定是否填补

缺失可能来自传感器、通信、佩戴中断或数据导出过程。缺失的位置和持续时间本身也是需要报告的数据质量信息。

研究可以选择：

- **保留缺失标记：** 使用能处理缺失输入的模型，或增加观测状态标记；
- **只使用连续完整片段：** 规则简单，但可能减少样本并改变样本构成；
- **对特定长度的缺口填补：** 必须预先规定适用条件、方法和上限；
- **排除过长缺失段：** 报告排除规则及受影响的受试者与样本数。

不存在适用于所有数据集、设备和研究任务的统一填补阈值。本仓库在具体实验中应通过配置文件记录所选择的规则。

### 模拟实时预测时尤其注意

假设在 `t` 时刻发出预测：

> 模型输入及其填补结果，不能使用 `t` 之后才出现的 CGM 读数。

例如，离线处理完整曲线时，可以看到缺口两端的读数；但若缺口后一端发生在预测时刻之后，用它插值并作为 `t` 时刻的输入，就泄漏了未来信息。

即使缺口两端都早于 `t`，也应在实验记录中写明填补方法，并区分填补值与真实观测值。一项在线低血糖预测研究就分别处理了训练数据与实时测试数据的缺失情况，说明两者的信息条件不能直接混为一谈。[3]

**目标值也要谨慎：** 如果未来目标时刻没有实际 CGM 观测，应事先规定是否排除该样本；不要把填补出的目标值不加标记地当成真实测量结果。

## 8. 异常值：标记、核查，而非盲目删除

遇到突变或极端读数时，先检查：

- 是否有设备提供的无效状态标记；
- 原始文件是否存在解析错误；
- 时间戳、单位或受试者是否错位；
- 附近是否有缺失、传感器更换或通信问题；
- 该变化是否可能是真实发生的血糖变化。

**仅凭曲线不平滑，不能断言某个读数是错误值。** 若实验需要剔除或修正，必须写明判定规则、受影响样本数及敏感性分析方案。

## 9. 辅助事件如何与 CGM 对齐？

进餐、胰岛素输注和活动可能来自不同设备或人工记录。对齐时要分别记录：

- 事件发生时间与事件被记录时间是否相同；
- 事件变量的单位与定义；
- 缺失事件表示“没有发生”，还是“没有记录”；
- 在预测时刻 `t`，事件信息是否已经可用；
- 事件记录与 CGM 记录是否使用同一时区。

**“没有记录进餐”不一定等于“确定没有进餐”。** 对缺失辅助信息的解释，应遵循数据集说明。

## 10. 滑动窗口应在规则明确后构造

血糖预测常使用历史 CGM 片段构造模型输入：

```text
截至 t 的历史读数 → 在 t 发出预测 → t + H 的目标读数
```

构造每个样本时应核对：

- 输入是否完全发生在 `t` 及之前；
- 目标是否处于预定的预测时距；
- 输入是否跨越不能直接连接的长缺失段；
- 窗口是否跨越受试者边界；
- 辅助变量在 `t` 时是否真实可获得；
- 填补值、真实观测值和缺失标记是否能区分。

相邻滑动窗口可能大量重叠。窗口构造与数据拆分的先后顺序，会影响测试结果是否可信；详见后续的数据泄漏笔记。

## 11. 每次预处理都应输出质量报告

建议为每个数据集或受试者记录：

| 质量项目 | 本次结果 |
| --- | --- |
| 原始记录数 | 待填写 |
| 时间戳无效／重复记录数 | 待填写 |
| 原始葡萄糖单位 | 待填写 |
| 观察到的采样间隔分布 | 待填写 |
| 缺失段数量与长度分布 | 待填写 |
| 被标记的异常记录数 | 待填写 |
| 被填补的输入值数量 | 待填写 |
| 被排除的目标值数量 | 待填写 |
| 最终可用预测样本数 | 待填写 |
| 预处理代码版本或 Git commit | 待填写 |

报告中应区分“原始观测”“变换后的观测”和“估计填补值”。
