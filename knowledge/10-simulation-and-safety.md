# 人工胰腺仿真研究与安全边界

> **笔记性质：** 科研证据与安全边界说明  
> **适用范围：** 离线研究、计算机仿真及论文阅读  
> **重要边界：** 本文不提供真实设备连接、控制参数或胰岛素给药指导。

## 1. 为什么需要仿真？

人工胰腺系统把传感器、控制算法和胰岛素输注设备连接成反馈环路。评价一个预测模型是否准确，与评价它参与控制后会产生什么后果，是不同的问题。

计算机仿真（in silico）允许研究者在**模拟的人体与设备环境**中，反复测试控制思路和预设场景。它有助于发现方法缺陷、比较不同方案并设计后续研究；但仿真结果取决于模拟器的假设，不能直接证明真实患者使用安全。[1][2]

## 2. 四种研究层次

| 层次 | 研究对象 | 可以回答的问题 | 不能直接推出 |
| --- | --- | --- | --- |
| 离线数据实验 | 已记录的 CGM 等数据 | 模型在指定测试集上的预测表现 | 接入控制系统后的表现 |
| 计算机仿真 | 虚拟受试者、传感器、泵与控制器 | 特定模拟条件下的系统表现和失败模式 | 真实人体中的疗效与安全性 |
| 受监测的人体研究 | 按研究方案使用的设备与受试者 | 受监测条件下的效果和风险 | 所有日常生活场景的表现 |
| 门诊或日常生活场景研究 | 更接近日常使用条件的系统 | 研究人群和条件下的实际使用表现 | 未研究人群、设备和条件的效果 |

FDA 指出，实验室研究和计算机建模可以提供重要信息，但理解设备在真实场景中是否按预期工作、是否存在相关安全问题，仍需要临床研究。[1]

**术语规则：** 在仓库中分别使用“离线预测结果”“仿真控制结果”“人体研究结果”，不要统一写成“已经验证有效”。

## 3. 仿真系统通常包含什么？

一个人工胰腺仿真研究可能包含：

1. **虚拟受试者：** 模拟葡萄糖与胰岛素相关的生理过程及个体差异；
2. **外部场景：** 例如进餐时间、餐食信息或其他研究设定；
3. **传感器模型：** 生成供控制器使用的模拟观测；
4. **设备模型：** 表示模拟输注设备及其行为；
5. **控制算法：** 根据模拟观测生成行动；
6. **评价程序：** 计算预先确定的结果指标。

一项早期原始研究介绍了由虚拟受试者、CGM 传感器误差模型和皮下胰岛素输注模型组成的仿真系统，用于闭环控制方法的临床前研究。[2]

> **注意：** 不同模拟器实现的生理机制、传感器误差及设备行为并不相同。使用前应查阅对应版本的文档，而不是仅凭“人工胰腺模拟器”这一名称判断它能模拟什么。

## 4. 仿真能够帮助检查什么？

在**纯仿真环境**中，研究者可以预先设计并比较：

- 不同虚拟受试者之间的表现；
- 预设进餐时间或组成变化下的表现；
- 有无进餐预告时的差异；
- 传感器噪声、缺失或通信中断下的表现；
- 控制器收到异常输入时的行为；
- 与预先选定的对照方法相比的结果；
- 模拟器参数变化后结论是否依然成立。

这些测试是**对特定模拟场景的审查**。某个场景没有出现问题，不等于未测试的情况也没有风险。

## 5. 首先记录仿真假设，而不是只记录分数

每项仿真实验至少应说明：

| 项目 | 需要记录的内容 |
| --- | --- |
| 模拟器 | 名称、版本、代码来源与许可 |
| 虚拟受试者 | 数量、类别、选择方法和适用范围 |
| 生理模型 | 关键假设及已知局限 |
| CGM 模型 | 测量误差、延迟、缺失如何表示 |
| 输注设备模型 | 仿真中实现了哪些行为及限制 |
| 场景 | 进餐、活动、昼夜和异常情况如何设定 |
| 控制器 | 输入、输出、更新频率及版本 |
| 对照方法 | 与新方法比较的基线是什么 |
| 随机性 | 随机种子和重复次数 |
| 评价 | 事先规定的主要指标、失败判据及计算方式 |

FDA 关于人工胰腺设备系统的指导文件讨论了系统组成、风险分析和非临床测试；具体监管要求应查阅适用地区及研究当时有效的官方文件，不能用本笔记替代合规判断。[3]

## 6. 怎样公平比较两个控制方法？

如果目的是比较方法 A 和方法 B，应尽量保持其他条件一致：

- 使用相同的模拟器及版本；
- 使用相同的虚拟受试者；
- 使用相同的测试场景与观察时长；
- 使用相同的传感器和设备模型；
- 采用相同的指标定义；
- 报告各虚拟受试者的结果，而非只挑选一个示例；
- 事先区分调参场景与最终测试场景。

如果 A 使用了未来进餐预告，而 B 没有，这不仅是算法差异，还是**输入信息不同**。报告中必须明确写出。

## 7. 安全分析关注哪些失败模式？

安全分析不应只问“平均 TIR 是否提高”，还要问：

- CGM 数据缺失、延迟或异常时，系统如何表现？
- 设备通信中断时，仿真如何记录或处理？
- 控制器输出不符合预设限制时，实验如何标记？
- 既往行动仍在发挥作用时，控制器是否正确考虑历史状态？
- 一个场景表现良好，另一个场景是否明显恶化？
- 是否出现低值区间时间增加或其他预先定义的不利结果？
- 是否有仿真程序崩溃、无效输出或无法完成的试验？

这里列的是**科研审查问题**，不是为真实设备提供故障处理规则。真实系统的安全设计、验证与使用必须由合格团队依据适用要求完成。

## 8. 指标与证据不能混淆

仿真研究可以报告模拟 CGM 轨迹的 TIR、TBR、TAR、低值事件以及算法和设备状态；具体定义见 [闭环控制评价](08-control-evaluation.md)。

但应在图表和正文中明确写出：

- “**仿真** TIR”，而不是笼统的“患者 TIR”；
- “**模拟**低值事件”，而不是未经研究定义就称作真实临床严重低血糖事件；
- “在**所测试的虚拟受试者和场景**下”，而不是“适用于所有患者”。

不能因为一个预测器在离线测试中误差更低，就跳过控制层面的独立评价。

## 9. 开源模拟器示例与使用边界

[simglucose](https://github.com/jxx123/simglucose) 是一个用于研究的 Python 1 型糖尿病模拟项目，项目说明提供虚拟受试者、场景生成与控制器测试接口。[4]

如果将来在本仓库使用它，应先核对并记录：

- 使用的版本或 Git commit；
- 项目文档描述的模型来源；
- 可用虚拟受试者及场景范围；
- 其传感器与设备模型实现；
- 软件许可和引用要求；
- 本仓库实验与其默认示例有哪些差别。

**使用开源模拟器，不等于获得真实医疗设备的验证或使用许可。** 不应将研究控制代码直接连接到真实胰岛素泵。

## 10. 本仓库建议采用的分阶段路线

```text
知识整理与文献核对
    ↓
离线血糖预测基线
    ↓
独立测试集与失败案例分析
    ↓
仅在隔离的仿真环境中研究控制问题
    ↓
记录仿真假设、异常与局限
```

这只是本仓库的**科研组织路线**，不是人体研究或设备开发审批路线。若研究计划涉及真实受试者或真实设备，应由具备资质的团队进行伦理、临床、安全和适用监管要求的评估。
